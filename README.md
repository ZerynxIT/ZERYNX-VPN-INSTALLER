# ZERYNX-VPN-INSTALLER

نصاب مستقل برای استقرار ZERYNX VPN روی حساب Cloudflare هر کاربر. این مخزن هیچ تغییری در ریپوی اصلی `ZERYNX-VPN` ایجاد نمی‌کند.

## انتشار
1. فایل‌های این مخزن در ریشه GitHub Pages قرار دارند.
2. در GitHub به **Settings → Pages** بروید.
3. **Deploy from a branch**، شاخه `main` و پوشه `/(root)` را انتخاب کنید.
4. پس از انتشار، لینک GitHub Pages را برای نصب‌کننده‌ها ارسال کنید.

## ساخت توکن با لینک آماده
دکمه **Create token** در صفحه نصب، فرم رسمی Cloudflare را با دسترسی‌های زیر از قبل پر می‌کند:
- **Account Settings — Read**: برای فهرست‌کردن حساب‌های قابل دسترس کاربر.
- **D1 — Edit**: برای ساخت دیتابیس.
- **Workers Scripts — Edit**: برای ایجاد/انتشار Worker و فایل‌های استاتیک.

Cloudflare پس از ورود، فرم توکن را نشان می‌دهد؛ کاربر باید دسترسی‌ها را بررسی کند، **Continue to summary** را بزند و سپس خودش **Create Token** را انتخاب کند. این لینک توکن را ایجاد نمی‌کند و هیچ دسترسی‌ای را بدون تأیید کاربر اعطا نمی‌کند.

هیچ مجوز جداگانه‌ای برای **Workers Scripts Read**، KV، DNS، Billing یا سایر سرویس‌ها در قالب توکن درخواست نمی‌شود. توجه کنید که مجوز **Edit** در Cloudflare ممکن است در همان منبع عملیات خواندن/نوشتن را هم پوشش دهد؛ نصب و به‌روزرسانی مستقیم Worker بدون مجوز مدیریت Worker ممکن نیست.

## رفتار نصاب
- UI دو زبانه فارسی/English با تغییر لحظه‌ای زبان و RTL/LTR است.
- فونت Vazirmatn و Inter بارگذاری می‌شوند و fallback محلی دارند.
- سورس Worker و فایل‌های پنل را از شاخه `main` مخزن عمومی `ZerynxIT/ZERYNX-VPN` دریافت می‌کند.
- D1 را با نام `zerynx-<worker-name>` می‌سازد.
- Worker را با bindingهای `DB` و `ASSETS` از طریق Cloudflare API منتشر می‌کند.
- پس از Deploy مسیر `/api/health` را برای بررسی اتصال D1 فراخوانی می‌کند.
- دکمه Update همان Worker را با آخرین سورس جایگزین می‌کند و دیتابیس قبلی را نگه می‌دارد.
- فقط اطلاعات غیرمحرمانه نصب (Account ID، Worker name و D1 ID) در LocalStorage همان مرورگر ذخیره می‌شود تا Update بعدی بتواند دیتابیس قبلی را پیدا کند.
- API Token در LocalStorage، URL، GitHub یا فایل‌های مخزن ذخیره نمی‌شود؛ پس از عملیات از فیلد و متغیر حافظه پاک می‌شود.
- درخواست‌های GET با timeout و retry محدود اجرا می‌شوند؛ عملیات تغییردهنده مانند ساخت D1 یا Deploy خودکار retry نمی‌شوند تا از اجرای تکراری جلوگیری شود.

## نکات امنیتی و محدودیت‌ها
- لینک قالب توکن فقط فرم Cloudflare را از قبل پر می‌کند؛ کاربر باید خودش وارد Cloudflare شود، دسترسی‌ها را بررسی کند و توکن را بسازد. این لینک OAuth نیست و به‌جای کاربر رضایت نمی‌دهد.
- توکن را فقط در دامنه GitHub Pages رسمی این مخزن وارد کنید. توکن به کد JavaScript صفحه دسترسی دارد و نباید صفحه را از fork یا دامنه ناشناس باز کرد.
- کاربر می‌تواند پس از نصب، توکن را از داشبورد Cloudflare لغو کند. برای Update بعدی باید توکن تازه با همین دسترسی‌ها بسازد.
- برای Update باید از همان مرورگر/دستگاه استفاده شود؛ پاک‌شدن LocalStorage اطلاعات اتصال نصب قبلی را از بین می‌برد.
- اگر حساب هنوز workers.dev subdomain نداشته باشد، نصاب آن را خودکار با مجوز گسترده‌تر ایجاد نمی‌کند؛ کاربر باید آن را در داشبورد Cloudflare فعال کند و سپس Update را اجرا کند.
- این نسخه از مرورگر مستقیماً به `api.cloudflare.com` و `raw.githubusercontent.com` درخواست می‌فرستد. اگر شبکه/مرورگر CORS را مسدود کند، درخواست ممکن است fail شود؛ timeout/retry مشکل CORS را دور نمی‌زند.
- استقرار واقعی end-to-end نیازمند حساب و توکن Cloudflare است؛ تغییرات این commit از نظر ساختار و منطق مرورگری بررسی شده‌اند، اما با حساب واقعی Cloudflare آزمایش نشده‌اند.
